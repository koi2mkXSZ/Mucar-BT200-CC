## Important control-flow ambiguity

The local analysis found:

  PIDV -> PIDV.toBasicDataStreamBean() -> BasicDataStreamBean.id

and DataStreamScene.preloadData() -> ELMDataViewUtil.add(pidv), only for
selected PIDV objects. This is evidence about an app data-stream subsystem,
but it is NOT evidence that proprietary Chery Delphi streams use that
subsystem. The method names and ELMDataViewUtil strongly suggest an
ELM-related UI path, which must be verified or ruled out by the actual
caller chain and diagnostic-driver data source.

The hidden Delphi item 76010020 has **not** been connected to PIDV, a native
GGP read, an OEM selection list, or a live list item. No such literal was found
in the inspected class-name search. The old attempt to substitute an EGR
description cannot be explained as a verified direct failure mode from
these reports: the exact patch bytes were not reexamined.

Therefore adding a check for 76010020 to BasicDataStreamBean may have no
visible effect at all. Do not modify the original APK on this basis.

## Missing dynamic diagnostic assets

The driver libCHERY_OLD.so was not found among the 25 ARM64 split library
names. The diagnostic package QIRUI_TY V10.22 was not present in the analyzed
local workspace; on-device separately downloaded QIRUI files require a
distinct ADB capture. Do not conclude the proprietary Delphi driver is
absent globally.
